Pivot · 状态与文档类型流程

matter 怎么从想法走到收口，每一步用什么类型的文档推进。基于 AI-docs/pivot-product.md。

1matter 状态机

一件事从被提出到正式收口要走过的 6 个状态。状态机回答"这件事现在推进到哪儿"，不回答"用什么文档推进"。

实箭头是状态迁移；虚线 ⟲ 是停留——比如 planning 期间可以创建 act 但不一定就要进 executing；finished / cancelled 之后可以创建 insight 但不一定立刻收口为 reviewed。是否推进，由触发文件本身的 status_change 字段说了算。

think 触发 act 触发 result 触发 insight 触发 恢复 / 反向 ⟲ 自循环（建文档但不推进状态）

2文档类型

5 种类型，回答"这份文档承担什么作用"。跟状态机正交，状态不会因为新增某类文档而自动改变。

think 分析

承载分析、澄清、方案推演和取舍讨论。也用于触发 paused 与 paused → 恢复。

act 行动

承载行动方案、执行记录、任务拆解。creator 和 owner 可不同（小组长创建、组员负责）。

verify 验证

对一组 act 给出 passed / failed / cancelled 判断 + 简短评价，结构化字段为 verifications[]。

result 结果

matter 的最终结论。一个 matter 只能有一个有效 result，outcome = finished / cancelled，触发状态迁移。

insight 复盘

事项收口后的复盘、经验、共识。只能在 finished / cancelled 状态下新增，触发 reviewed。

3状态 × 文档类型 允许矩阵

每个状态下哪些文档类型可以新建。绿色允许、红色禁止、黄色有条件。

planning 允许 允许 允许 禁止 禁止 事项还在计划阶段，暂无最终结果可言

4状态迁移规则

每条迁移由哪种文档触发。status_change 字段写在触发文件上。

  • planning→executing 由一篇 act 触发，事项正式进入执行
  • planning→paused 由一篇 think 触发，说明为什么暂停
  • executing→paused 由一篇 think 触发，说明卡在哪里
  • paused→planning 由一篇 think 触发，说明为什么可以恢复
  • paused→executing 由一篇 think 触发，说明恢复后回到执行
  • executing→finished 由一篇 result（outcome=finished）触发
  • executing→cancelled 由一篇 result（outcome=cancelled）触发
  • finished→reviewed 由一篇 insight 触发，整个生命周期收口
  • cancelled→reviewed 由一篇 insight 触发

5关键操作要点

新文件从已有文件长出来

除事项第一篇外，新 think / act / verify 都从某个文件卡片发起。系统自动把当前文件写入新文件的 quote。

  • 第一篇允许直接创建（通常是 think，也可以是 act），无 quote
  • verify 内容可覆盖多个 act（通过 verifications[]），但入口仍挂在某个文件卡上

creator 与 owner 分工

所有文件都有这两个字段：creator 是创建者，owner 是责任人。

  • think / verify / insight：默认 creator = owner
  • act：可以不同（小组长创建，组员负责执行）
  • verify.owner = 判断责任人，未必是被验证 act 的执行者

verify 的 judgement

每条 verifications[i] 必须给出三选一结果 + 简短评价：

  • passed：交付结果成立
  • failed：当前结果不可接受
  • cancelled：明确不再推进，正式记录

result 是事项级的特例

matter 只能有一个有效 result，对象就是 matter 本身。

  • quote / refer 可以为空
  • 不要求建立在某篇 verify 之上（系统不强制"先验证后结束"）
  • 入口建议放在详情页顶部，作为页面级动作，明示这是收口操作

暂停与恢复都用 think

paused 不是执行结果，而是对当前局面的判断。所以触发暂停 / 恢复都用 think。

  • 暂停 think：写清为什么暂停 / 卡在哪里 / 什么条件可以恢复
  • 恢复 think：写清为什么可以恢复 / 之前的条件如何变化 / 回到 planning 还是 executing

正文不强约束，结构靠 index

5 种文档类型的正文都没有强制模板，只是推荐写法。真正的硬约束在：

  • index 中的结构化字段（type / quote / verifications / outcome / status_change）
  • 当前状态下允许的文档类型
  • 合法的 status_change 路径
